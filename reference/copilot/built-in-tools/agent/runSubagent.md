# Copilot Chat 内置工具：`agent.runSubagent`（`runSubagent`）

> 目的：把 Copilot Chat 的 `runSubagent`（上下文隔离子代理）语义整理成可实现、可对齐的规格说明，供 Tripilot 做功能对齐。
>
> 本文是基于公开资料的**转述与归纳**，不复制官方原文。

## 一句话概述
`runSubagent` 允许主会话把一段任务**委派给一个上下文隔离的自治子代理**执行；子代理在自己的上下文窗口里完成工作，结束后仅把**最终结果**回传主会话。

## 官方语义来源（公开）
- VS Code 文档：Chat sessions（含“Context-isolated subagents”章节）
  - https://code.visualstudio.com/docs/copilot/chat/chat-sessions
- VS Code 文档：Agents overview（对“subagents”的定位与适用场景）
  - https://code.visualstudio.com/docs/copilot/agents/overview

## 核心行为（对齐要点）
### 1) 上下文隔离
- 子代理拥有**独立的上下文窗口**；它的中间推理、临时信息、过程性工具调用不应“污染”主会话上下文。
- 子代理的目标是为“复杂、多步骤”的子任务提供更好的上下文管理能力（例如：调研、分析、把问题拆分后分别处理）。

### 2) 自治运行，但不是后台异步
- 子代理会**自治执行到结束**（中途不会像交互式对话那样频繁停下来等用户确认）。
- 但它**不是异步后台任务**：调用 `runSubagent` 时，主会话会等待子代理结束并拿到最终结果再继续。

### 3) 只回传最终结果（Result handoff）
- 子代理完成后**仅回传最终结果**到主会话。
- 主会话应把该结果当作一个“工具返回值”或“一段总结性输出”，而不是把子代理的完整过程日志注入回主上下文。

### 4) 工具与模型继承（默认）
- 默认情况下：子代理使用**与主会话相同的 agent**。
- 子代理默认拥有**与主会话相同的工具集合**（但有一个关键例外：子代理通常**不能再创建其他子代理**）。
- 子代理默认使用**与主会话相同的模型**。

### 5) 可选：让子代理使用不同 agent（实验性）
- 公开文档提到存在实验性能力：允许子代理使用不同的 built-in/custom agent。
- 相关设置项：`chat.customAgentInSubagent.enabled`
- 同时文档指出：若某自定义 agent 不希望被用作 subagent，可在 agent 定义里设置 `infer: false`（以阻止其被用于 subagent）。

## 调用方式（用户侧体验）
### 在 Copilot Chat 里
- 需要在工具选择器（tool picker）里启用 `runSubagent`。
- 如果通过自定义 prompt 文件或 custom agent 的 frontmatter 声明工具列表，需要把 `runSubagent` 写入 `tools`。

> Tripilot 对齐建议：你可以保持同样的“工具开关”模型——只有当用户允许/启用该工具时，智能体才会发起 subagent。

## 输入/输出规格（实现导向）
> 官方文档倾向于把它当作“可被 LLM 调用的工具”，但实现细节对用户是抽象的。这里给出**对齐实现的建议规格**。

### 建议输入（Input）
- `prompt`: string
  - 子代理需要执行的任务描述（应尽可能自包含）
- `description`: string
  - 3–5 个词的短描述，用于 UI/日志展示（例如："Research auth options"）

### 建议输出（Output）
- `result`: string
  - 子代理的最终产出（总结/结论/清单/建议等）

### 不应输出
- 不应把子代理的完整工具调用过程、逐步思考链、长篇中间草稿作为主会话输出（最多可选择性地在“调试视图”里展示）。

## 限制与边界（实现必须考虑）
- **不可递归**：子代理通常不应再调用 `runSubagent` 去创建“孙子代理”。（公开文档明确提到工具例外：子代理不具备创建 subagent 的能力。）
- **会话一致性**：子代理最终输出应作为一次工具调用的返回值进入主会话，主会话继续后续计划/执行。
- **取消/中断**：如果主会话取消当前请求，应中断子代理运行。
- **资源与成本**：子代理隔离上下文不代表“免费”——它依然消耗模型调用与工具调用预算。建议限制并发数量、限制最大步骤/最大耗时。

## 典型适用场景（When to use）
- 调研/阅读外部资料并产出摘要（主会话保持干净）
- 对大型任务做拆分：让多个子代理分别分析不同模块/文件/方案，再把结论汇总
- 需要大量只读工具调用（搜索、读取、归纳）但不希望堆满主会话过程

## 不适用场景（When NOT to use）
- 简单的一步回答（开子代理反而慢）
- 需要频繁与用户确认每一步的交互式任务
- 需要长时间后台跑（子代理不是异步后台）

## Tripilot 对齐实现建议（落地清单）
1. **上下文隔离**：为 subagent 建独立 conversation/context；主会话只注入：输入任务 + 最终返回。
2. **工具继承 + 禁止递归**：默认复用主会话工具集合，但在 subagent 环境中禁用 `runSubagent`。
3. **自治执行**：subagent 不要要求用户中途交互；遇到不确定项应做合理假设并声明。
4. **返回格式**：约束为单段 `result`（必要时可用小标题/列表），避免把“日志”带回主会话。
5. **取消传播**：主会话 stop/cancel 应取消 subagent。
6. **配额与保护**：限制最大步数/最大工具调用数/最大耗时，防止失控。
7. **可观测性**：把子代理的中间过程放到 Tripilot 的 debug view（可选），而不是主 chat transcript。

## 示例（对齐用提示词模版）
- 调研型：
  - “使用 `runSubagent` 调研 X，并用 8–12 条要点总结；只返回结论。”
- 拆分型：
  - “把任务拆成 3 个子问题，分别用 `runSubagent` 处理，然后在主会话合并成一个行动计划。”
